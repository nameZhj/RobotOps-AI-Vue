# 可视化大屏显示规范

## 目标和显示模式

可视化大屏用于持续展示机器人集群状态，不是普通后台页面。它采用固定的 1920 × 1080（16:9）设计画布，整张画布只允许统一等比例缩放。不得因为窗口尺寸或屏幕比例变化而重排内部组件。

## 设计画布与缩放

- 设计尺寸：1920 × 1080 CSS px。
- 缩放比例：`scale = min(viewportWidth / 1920, viewportHeight / 1080)`。
- 画布通过 `top: 50%`、`left: 50%` 和 `translate(-50%, -50%)` 居中，再对完整画布应用同一个 `transform: scale(scale)`。
- 浏览器窗口、显示器、全屏尺寸变化后重新计算 scale；ResizeObserver 和 window / visualViewport / fullscreen 监听器必须在卸载时清理。
- 16:10、4:3、21:9 和竖屏继续保持 16:9，剩余区域留白。4K 屏幕允许按同一比例放大。
- 不得单独缩放文字、地图、图表或面板。地图 Canvas / WebGL 可按 devicePixelRatio 提高绘制分辨率，但不能改变 CSS 布局比例。

## 当前信息架构

大屏主体采用三栏布局，地图是页面视觉中心：

| 区域 | 设计宽度 | 内容 |
|---|---:|---|
| 左栏 | 330 px | 设备状态、巡检统计、巡检事件 |
| 中央 | 自适应，最大 | PGM / PCD 地图、机器人位置、任务路线和事件点位 |
| 右栏 | 370 px | 现场视频、执行中任务、等待任务和已完成任务 |

中央地图区域必须明显大于左右侧栏。不要再把地图压缩成普通卡片，也不要使用四张等权重 KPI 卡片替代主地图。

### 设备状态

展示设备 ID、名称、所属区域、连接状态和电量。状态至少区分在线、异常、离线和未知。未知或过期数据不能继续显示为在线。颜色之外必须保留状态文字。

### 地图和定位

- 复用 `src/modules/maps/components/MapViewport.vue`，使用 Three.js 显示 PGM 栅格地图和 PCD 点云。
- PGM 必须与 ROS YAML 配套，读取 resolution、origin、negate 和 frame_id。不得猜测地图分辨率、原点或坐标系。
- 机器人位置、任务路线和事件点位必须转换到同一个 map 坐标系后再叠加。
- 自定义地图导入后，必须隐藏演示用机器人位置、路线和事件点位，直到对应坐标系的真实数据可用。
- 地图渲染区域可包含导入 PGM、YAML、PCD 的入口，以及地图源、坐标系、图例和加载错误提示。
- 点云大文件应遵守大小限制；生产环境需要 Worker / LOD 时单独规划，不得在本页面堆积大型点云状态。

### 巡检统计和事件

巡检统计需要展示计划点位、已完成点位、待复核数量和完成率。事件条目应包含发生时间、级别、设备、事件描述和点位 ID / 区域；有服务端图片时显示现场图片或关键帧。仅有坐标而没有图片时，可以显示点位缩略图，但不能把缩略图标为现场照片。

当前尚无巡检统计、事件和事件媒体 API，因此这些数据在演示模式必须标注为演示内容。接入真实数据后，不得继续使用硬编码事件替代服务端记录。

### 现场视频

- 视频入口通过按钮控制播放，未播放时不持续占用摄像头流。
- 当前播放器使用 HTML `video`，播放源由可选配置 `VITE_COMMAND_CENTER_VIDEO_URL` 提供。
- 播放地址必须是浏览器原生支持的媒体 URL。RTSP 不能直接由 HTML `video` 播放；生产环境需由视频网关转换为浏览器兼容格式。
- 若需要跨浏览器 HLS 或 WebRTC，需要另行接入 HLS.js 或 WebRTC 播放器和信令，不得将其假设为普通 `video src` URL。
- 未配置视频源时，按钮应显示明确的配置提示，不得显示伪造的直播画面。

### 任务执行

- 展示执行中、暂停、等待调度、已完成、失败和取消等状态。
- 正在执行的任务显示任务 ID、名称、设备和整体进度；已完成任务独立分组显示。
- 当前 `TaskSummary` 只有整体状态和进度百分比。没有后端步骤明细时，只能展示“已完成百分比 / 剩余百分比”，不得推断或编造具体步骤完成情况。
- 任务列表过多时，优先展示关键任务和数量摘要，不得使用滚动区域。

## 石墨薄荷主题

大屏采用低饱和石墨底色，以薄荷青突出地图路径和主要数据，用荧光黄绿提示巡检节点，珊瑚红表示告警。

| 用途 | 色值 |
|---|---|
| 主背景 | `#090D12` |
| 画布渐变 | `#0D1318` |
| 面板 | `#141C24` |
| 主要文字 | `#E8F0F2` |
| 次要文字 | `#8FA2A6` |
| 主强调色：薄荷青 | `#62E6D0` |
| 辅助强调色：荧光黄绿 | `#C7F36D` |
| 告警色 | `#FF6B5A` |
| 注意色 | `#E5B85C` |

背景和面板负责区分层次，强调色只用于关键指标、任务路线、交互和状态。禁止为每个面板单独添加高亮霓虹边框或大面积发光效果。

## 滚动条规则

html、body、#app、大屏视口、1920 × 1080 设计画布和内部组件均不得出现水平或垂直滚动条。禁止 `overflow: auto`、`overflow: scroll`、虚拟滚动和依赖滚动访问内容的布局。

信息过多时，减少条目、精简文字、调整固定网格或轮播内容；不得裁掉业务关键信息，也不得增加滚动区域。

## 与普通页面的区别

| 项目 | 普通业务页面 | 可视化大屏 |
|---|---|---|
| 布局方式 | 响应式重排 | 固定 16:9 画布 |
| 断点行为 | 改变列数和排列 | 不改变内部布局 |
| 缩放方式 | CSS 自适应布局 | 整张画布统一 transform scale |
| 滚动条 | 允许局部滚动 | 完全禁止 |
| 宽高比 | 可随容器变化 | 始终保持 16:9 |
| 留白 | 内容通常填充可用空间 | 居中显示，允许四周留白 |

## Vue 和 CSS 实现要求

1. 大屏使用独立路由，不套用 AppLayout。
2. 大屏样式独立维护，不依赖普通后台页面断点和 Element Plus 主题覆盖。
3. 所有连接、ResizeObserver、DOM listener、Three.js geometry、material、texture 和 renderer 都必须有对应清理逻辑。
4. Mock 指标、定位、路线和事件必须清晰标记，不得冒充实时设备数据。
5. 修改后执行 `npm run typecheck` 和 `npm run build`，并按人工检查清单验收。

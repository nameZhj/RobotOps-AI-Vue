# 可视化大屏显示规范

## 目标

可视化大屏不是普通后台页面。它用于固定布局的监控显示，不能随着窗口宽度不断改变卡片排列，也不能通过滚动条访问被挤出屏幕的内容。

## 设计画布

- 设计尺寸：1920 × 1080 px。
- 设计比例：16:9。
- 唯一允许的整体适配方式：对完整画布做等比例缩放。
- 基准尺寸不随显示器分辨率变化；不要为 1366、2560 或 4K 单独维护另一套布局。

## 缩放计算

读取可视区域的实际宽度和高度：

```ts
const scale = Math.min(
  viewportWidth / 1920,
  viewportHeight / 1080,
)
```

将同一个 scale 同时应用于画布宽度和高度。画布通过 top: 50%、left: 50% 和 translate(-50%, -50%) 定位在视口中心，再使用 transform: scale(scale)。

不能分别计算 X/Y scale，否则文字、圆形、图标和图表都会变形。

## 不同比例的屏幕

- 16:9：画布正常铺满可用区域。
- 16:10、4:3、21:9：按较短的一边计算比例，画布居中，剩余区域留白。
- 竖屏：继续保持 16:9，将整张画布缩小并居中。不要把三列布局改成一列。
- 4K 和更高分辨率：允许按同一比例放大完整画布。

留白是预期行为，不要用拉伸、裁切或重新排列填满留白区域。

## 滚动条规则

大屏模式必须同时限制：

- html
- body
- #app
- 大屏根容器
- 设计画布

上述节点均不得出现水平或垂直滚动条。大屏组件不得使用 overflow: auto、overflow: scroll、内部滚动容器或虚拟滚动。

设计画布本身固定为 1920 × 1080 并使用 overflow: hidden。所有内容必须在画布内完成排布。若某个面板内容过多，应减少展示条数、精简文字、使用省略号或重新安排固定网格，不允许增加滚动条。

## 与普通页面的区别

| 项目 | 普通业务页面 | 可视化大屏 |
|---|---|---|
| 布局方式 | 响应式重排 | 固定 16:9 画布 |
| 断点行为 | 改变列数和排列 | 不改变内部布局 |
| 缩放方式 | CSS 自适应布局 | 整张画布统一 transform scale |
| 滚动条 | 允许局部滚动 | 完全禁止 |
| 宽高比 | 可随容器变化 | 始终保持 16:9 |
| 留白 | 内容通常填充可用空间 | 居中显示，允许四周留白 |
| 典型场景 | 表格、表单、管理页面 | 指挥中心、监控大屏 |

## Vue 实现要求

1. 大屏使用独立路由，不套用 AppLayout。
2. 使用 ResizeObserver 监听视口尺寸，并在 onBeforeUnmount 中 disconnect。
3. 大屏进入时给 html/body 加上 visualization-mode class，退出时移除。
4. 大屏 CSS 独立维护在 visualization 模块，不依赖普通后台页面的断点样式。
5. 内容、状态和图表必须在设计尺寸内完整排布。
6. Mock 指标必须清晰标注，不得冒充实时设备数据。

- 页面与缩放：src/modules/visualization/views/CommandCenterView.vue
- 画布样式：src/modules/visualization/views/command-center.css

# 可视化大屏显示规范

## 目标

可视化大屏不是普通后台页面。它用于固定布局的监控显示，不随着窗口宽度改变卡片排列，也不能通过滚动条访问被挤出屏幕的内容。

## 设计画布

- 设计尺寸：1920 × 1080 CSS px。
- 设计比例：16:9。
- 唯一允许的整体适配方式：对完整画布做等比例缩放。
- 基准尺寸不随显示器分辨率变化；不要为 1366、2560 或 4K 单独维护另一套布局。
- 画布内的组件、文字、间距、边框和图表都使用这套设计坐标。

## 缩放计算

读取大屏视口的实际宽度和高度：

```ts
const scale = Math.min(
  viewportWidth / 1920,
  viewportHeight / 1080,
)
```

将同一个 `scale` 同时应用于画布宽度和高度。画布通过 `top: 50%`、`left: 50%` 和 `translate(-50%, -50%)` 定位在视口中心，再使用 `transform: scale(scale)`。

不能分别计算 X/Y scale，否则文字、圆形、图标和图表都会变形。禁止只缩放某个面板或单独调整文字比例。

## 不同比例的屏幕

- 16:9：画布按视口大小缩放，完整显示。
- 16:10、4:3、21:9：以较短的一边为准计算比例，画布居中，剩余区域留白。
- 竖屏：继续保持 16:9，将整张画布缩小并居中。不要把三列布局改成一列。
- 4K 和更高分辨率：允许按同一比例放大完整画布。
- 浏览器缩放、窗口大小变化、显示器切换和全屏切换后，都必须重新计算 scale。

留白是预期行为，不要用拉伸、裁切或重新排列填满留白区域。

## 滚动条规则

大屏模式必须同时限制：

- html
- body
- #app
- 大屏视口
- 1920×1080 设计画布
- 设计画布内的所有面板

上述节点均不得出现水平或垂直滚动条。禁止在大屏内部使用 `overflow: auto`、`overflow: scroll`、虚拟滚动或依赖滚动才能访问的内容。可以使用 `overflow: hidden` 裁掉装饰性溢出，但不能裁掉业务信息。

所有信息必须在设计画布内完成排布。若某个面板内容过多，应减少展示条数、精简文字、使用省略号、调整固定网格，或按时间轮播不同信息；不得增加滚动条。

## 与普通页面的区别

| 项目 | 普通业务页面 | 可视化大屏 |
|---|---|---|
| 布局方式 | 响应式重排 | 固定 16:9 画布 |
| 断点行为 | 改变列数和排列 | 不改变内部布局 |
| 缩放方式 | CSS 自适应布局 | 整张画布统一 transform scale |
| 滚动条 | 允许局部滚动 | 完全禁止 |
| 宽高比 | 可随容器变化 | 始终保持 16:9 |
| 留白 | 内容通常填充可用空间 | 居中显示，允许四周留白 |
| 典型场景 | 表格、表单、管理页面 | 指挥中心、监控大屏 |

## Vue 和 CSS 实现要求

1. 大屏使用独立路由，不套用 AppLayout。
2. 根节点固定覆盖整个视口，使用 `100dvh`，并设置 `overflow: hidden`。
3. 使用 ResizeObserver 监听视口尺寸，在组件卸载时 disconnect。
4. 大屏进入时给 html/body 加上 `visualization-mode` class，退出时移除。
5. 大屏样式独立维护，不依赖普通后台页面的断点样式。
6. 设计画布固定为 1920×1080，不在画布内部根据窗口宽度重新排列内容。
7. 对 ECharts、Canvas、WebGL 等位图内容，按设备像素比配置绘制分辨率，避免高分辨率显示器上模糊；CSS 视觉缩放比例仍然只能有一个。
8. Mock 指标必须清晰标注，不得冒充实时设备数据。
